Section 01 Section 01

Architecture globale et flux réseau System Architecture & Network Flow

1. Hyperviseur VMware (Bridged) & Debian 12 1. VMware Hypervisor (Bridged) & Debian 12

La machine virtuelle Debian 12 (Bookworm) est rattachée au réseau local en Bridged afin d'obtenir une adresse IP dédiée sur votre LAN. The Debian 12 (Bookworm) VM uses Bridged networking so it receives its own IP address directly on your LAN.

2. DuckDNS & Box NAT (Ports 80 / 443) 2. DuckDNS & Router NAT (Ports 80 / 443)

DuckDNS suit l'IP publique de votre box ; la box redirige uniquement les ports TCP 80 et 443 vers la VM (jamais le port 81). DuckDNS tracks your router's public IP; your router forwards only TCP ports 80 and 443 to the VM (never port 81).

3. Nginx Proxy Manager SSL & proxy-net 3. Nginx Proxy Manager SSL & proxy-net

Nginx Proxy Manager délivre le certificat Let's Encrypt, force le HTTPS et relaie le trafic vers nextcloud-app:80 via le réseau Docker proxy-net. Nginx Proxy Manager provisions Let's Encrypt TLS certificates, enforces HTTPS, and proxies requests to nextcloud-app:80 over Docker network proxy-net.

4. Nextcloud + MariaDB isolée + Redis 4. Nextcloud + Isolated MariaDB + Redis

Nextcloud fonctionne avec une base MariaDB dédiée sur volume persistant et Redis pour accélérer le cache applicatif et le verrouillage des fichiers. Nextcloud pairs with a dedicated MariaDB database on a persistent volume plus Redis for fast caching and transactional file locking.

Section 03 Section 03

IP statique (/etc/network/interfaces), DHCP, CGNAT & NAT Loopback Static IP (/etc/network/interfaces), DHCP, CGNAT & NAT Loopback

Choisissez une adresse IP statique hors de la plage DHCP de votre box (ou déclarez une réservation DHCP liée à l'adresse MAC de la VM), adaptez l'interface (ens33) et la passerelle, puis appliquez : Pick a static IP outside your router's DHCP pool (or configure a DHCP static lease by VM MAC address), match your interface (ens33) and gateway, then apply:

bash — /etc/network/interfaces 
sudo tee /etc/network/interfaces > /dev/null <<'EOF'
source /etc/network/interfaces.d/*

auto lo
iface lo inet loopback

allow-hotplug ens33
iface ens33 inet static
    address 192.168.1.50/24
    gateway 192.168.1.1
    dns-nameservers 1.1.1.1 9.9.9.9
EOF

sudo systemctl restart networking
ip -br a
ping -c 3 1.1.1.1
Hors plage DHCP / Réservation MAC Outside DHCP Pool / MAC Reservation

Si la box distribue 192.168.1.10 à 192.168.1.100, choisissez par exemple 192.168.1.50 uniquement si elle est exclue du DHCP ou réservée sur la box. If your router leases 192.168.1.10–192.168.1.100, use 192.168.1.50 only if excluded from DHCP or reserved by MAC address.

CGNAT & NAT Loopback CGNAT & NAT Loopback

Vérifiez que l'IP publique vue sur Internet correspond à l'IP WAN de la box (pas de blocage CGNAT). Si le domaine échoue en Wi-Fi local mais marche en 4G/5G, votre box manque de NAT loopback. Check that your observed public IP matches your router's WAN IP (no CGNAT port block). If the domain works on 4G/5G but fails on home Wi-Fi, your router lacks NAT loopback.

Contrôle : ip -br a affiche votre IP fixe et ping -c 3 1.1.1.1 répond à 100 %. Action: Match 192.168.1.50/24 and the gateway to your router. Why: Your router's port forward rule sends ports 80 and 443 to this exact IP. Check: ip -br a shows your static IP and ping -c 3 1.1.1.1 succeeds.
